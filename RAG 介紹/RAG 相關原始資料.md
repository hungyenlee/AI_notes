## 原始資料

### 使用者

RAG是甚麼

### Codex

RAG 是 **Retrieval-Augmented Generation**，中文常譯為「檢索增強生成」。

簡單說：它是在讓 AI 回答前，先去「查資料」，再根據查到的內容回答。

一般大語言模型只靠訓練時學到的知識回答，可能過時、記錯或亂編。RAG 會多加一步：

1. 使用者提問
2. 系統到文件庫、資料庫、網站、公司內部知識庫等地方搜尋相關資料
3. 把搜尋到的片段交給模型
4. 模型根據這些資料產生答案

例如你問：「我們公司請假規則是什麼？」  
如果 AI 只靠模型知識，它不會知道你公司的制度。  
但如果用 RAG，它可以先從公司 HR 文件裡找到請假規定，再整理成回答。

RAG 常用在：

- 企業知識庫問答
- 客服機器人
- 法規、醫療、金融文件查詢
- 內部文件搜尋
- 幫 AI 引用來源，減少幻覺

一句話版：**RAG 就是讓 AI 先查可信資料，再回答問題。**

### 使用者

AI為何需要RAG? 哪裡需要?

### Codex

AI 需要 RAG，核心原因是：**模型本身不是資料庫，也不是即時搜尋引擎。**

大語言模型擅長「理解、整理、推理、生成文字」，但它有幾個限制：

1. **知識可能過時**  
   模型只知道訓練到某個時間點以前的東西。公司最新政策、今天的價格、最新法規，它可能不知道。

2. **不知道你的私有資料**  
   例如公司 SOP、內部文件、客服紀錄、產品規格、合約條款，這些通常不在模型訓練資料裡。

3. **容易幻覺**  
   如果模型沒有足夠資料，它可能硬編一個看起來合理的答案。RAG 可以讓它先看資料再回答，降低亂答機率。

4. **需要可追溯來源**  
   很多場景不能只要「AI 說的」，還要知道答案來自哪份文件、哪一段內容。

**哪裡需要 RAG？**

凡是答案需要依賴「特定資料來源」的地方，就很適合 RAG。

常見場景：

| 場景 | 為什麼需要 RAG |
|---|---|
| 企業知識庫 | 回答公司內部制度、流程、SOP |
| 客服機器人 | 根據產品 FAQ、保固條款、訂單資料回答 |
| 法規/合約查詢 | 需要引用條文與來源，不能亂編 |
| 醫療/金融文件 | 高風險領域，需要根據可信資料 |
| 技術文件助手 | 根據最新 API 文件、版本說明回答 |
| 個人筆記助理 | 從你的筆記、PDF、會議紀錄找答案 |
| 電商/商品推薦 | 根據即時庫存、價格、商品描述回答 |

不一定需要 RAG 的情況：

- 寫詩、改文案、腦力激盪
- 一般常識問題
- 翻譯、摘要你已經貼上的文字
- 寫程式邏輯，但不依賴私有或最新資料

一句話：

**只要 AI 的答案需要「查某個資料庫/文件/最新資訊」才可靠，就需要 RAG。**
