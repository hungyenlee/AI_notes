## 一句話

單元測試適合成為測試金字塔底部，因為它便宜、快速，最適合大量保護細節邏輯。

## 內容

單元測試通常針對 function、class 或 module 這類較小的程式單位，重點是驗證商業邏輯、邊界條件與例外處理是否符合預期。它通常會避開真實資料庫、網路、外部 API 或 UI，讓測試可以穩定、快速地反覆執行。

底層測試數量多的好處，是每次修改後都能用低成本取得回饋，而且失敗時比較容易定位到問題所在。不過單元測試仍應測可觀察行為，而不是把內部實作細節綁死，否則重構時會變成阻力。
