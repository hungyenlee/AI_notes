標籤：#AI #軟體測試 #冒煙測試

## 一句話

冒煙測試很適合放在 build 或部署完成後，作為 CI/CD 流程中的快速健康檢查。

## 內容

冒煙測試常出現在新 build 產生後、部署到測試環境後、部署到 staging 後，或正式環境部署完成後。它可以手動執行，也可以自動化，例如檢查健康檢查 API、首頁是否回傳 200、登入 API 是否可用、服務是否連得上資料庫，或跑少量最重要的 E2E 測試。

在 CI/CD 裡，冒煙測試可以作為後續流程的 gate。通過時，流程才繼續進入更完整的測試或發布觀察；失敗時，流程應該停下來，讓團隊先處理 build、部署、設定或環境問題。
