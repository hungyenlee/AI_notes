## 一句話

Live Test 的最大風險是測試失敗會影響真實使用者、真實資料或真實外部服務。

## 內容

Live Test 的真實性很高，但代價是風險也高。測試如果沒有控制好，可能會寫入錯誤資料、寄信給真實使用者、建立真實訂單、觸發真實付款、修改正式資料，甚至造成服務中斷。

因此 Live Test 通常要把「可驗證」和「不傷害正式環境」一起設計。常見作法包括使用專用測試帳號、測試 tenant、測試商品、測試付款模式、可追蹤的 test flag，以及測試完成後可清理的資料。寄信流程可以走正式寄信服務，但收件者應限制在指定測試信箱；付款流程可以驗證串接是否正常，但不應誤觸真實扣款。

Live Test 也需要搭配監控、告警、少量流量、feature flag 和快速回滾能力。它不是把測試搬到正式環境而已，而是要讓正式環境中的驗證可控、可觀察、可復原。
