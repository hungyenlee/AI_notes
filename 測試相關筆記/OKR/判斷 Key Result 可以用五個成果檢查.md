#AI #OKR #KeyResult #成果思維 #知識卡

## 一句話

判斷一段描述是不是 Key Result，可以檢查它是否呈現可驗證的成果變化，而不是團隊準備執行的動作。

## 內容

可以先觀察句子的主詞。如果描述的是「我或團隊要做什麼」，通常比較接近工作內容；如果描述的是使用者、產品、系統、流程或指標將產生什麼變化，才比較接近 KR。這是一種快速篩選方式，但仍需要搭配下面五個問題確認。

**幾個檢查技巧**

1. **能不能被驗證？**  
   KR 應該能回答：「到期末，我怎麼知道它達成了？」  
   例如：
   - 任務：整理測試案例
   - KR：核心流程測試案例覆蓋率達到 80%

2. **有沒有結果狀態？**  
   如果只是「完成、建立、研究、導入、開發」，要小心它可能只是工作內容。  
   可以追問：「完成之後帶來什麼改變？」
   - 任務：導入自動化測試
   - KR：回歸測試時間從 3 小時降到 45 分鐘

3. **能不能不用指定做法？**  
   好的 KR 通常不綁死方法，而是描述想要的結果。
   - 任務：使用 Google Maps API
   - KR：95% 以上地點能在城市地圖上正確顯示

4. **是否有可衡量標準？**  
   KR 不一定每個都要是數字，但最好有明確驗收條件。
   - 任務：改善手機版
   - KR：手機版可完成搜尋、收藏、查看地圖三個主要流程

5. **問「所以呢？」**  
   看到一個疑似 KR，問自己：「所以這件事完成後，誰得到了什麼改善？」
   - 任務：新增標籤功能
   - 改寫成 KR：使用者能新增、編輯、刪除標籤，並用標籤篩選收藏地點

可以先用「透過完成＿＿，讓＿＿能夠＿＿，並用＿＿確認成果」展開思考，再刪除前面的工作手段，只保留後半段的成果。例如「導入自動化測試」是任務；「回歸測試時間從 3 小時降到 45 分鐘」才是 KR。「使用 Google Maps API」是手段；「95% 以上地點能正確顯示，且標記可點擊進入店家頁」才是可驗證成果。
