## 一句話

風險分析是判斷哪些地方最值得優先測。

## 說明

Risk Analysis 會在測試前先判斷：

- 哪些地方最容易出問題？
- 哪些地方一旦出問題影響最大？

因為測試時間有限，不可能把所有功能都測到一樣完整，所以要根據風險決定測試資源的分配。

常見判斷維度包括：

| 維度 | 問題 |
| --- | --- |
| 發生機率 | 這裡容易壞嗎？最近有改嗎？邏輯複雜嗎？ |
| 影響程度 | 壞了會很嚴重嗎？會影響付款、資料、安全、正式使用者嗎？ |

## 高風險區域

通常會優先測：

- 付款
- 訂單
- 權限
- 資料寫入
- 第三方 API
- 最近改動大的地方

## 重點

風險分析不是單純列測試項目，而是決定測試深度與測試優先順序。
