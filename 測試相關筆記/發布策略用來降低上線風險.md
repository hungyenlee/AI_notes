## 一句話

發布策略是決定版本要怎麼安全上線，而不是只問「測完了沒」。

## 內容

Release Strategy 關心的是：

> 這個版本要怎麼推出，才能降低上線風險？

測試不是結束在「測完」，而是要延伸到版本如何推出、如何觀察、出問題時如何回退。

## 常見策略

| 策略                    | 說明                               |
| --------------------- | -------------------------------- |
| Big Bang Release      | 一次全部上線                           |
| Blue-Green Deployment | 新舊環境並行，確認後切換流量                   |
| Canary Release        | 先給少量使用者用，沒問題再逐步放大                |
| Feature Flag          | 功能先部署，但用開關控制是否開放                 |
| Rollback Plan         | 如果壞了，怎麼快速退回上一版                   |
| Staged Rollout        | 分批釋出，例如 5% -> 25% -> 50% -> 100% |

## 上線時常搭配

- 上線前自動化測試
- Smoke Test
- 小流量驗證
- 監控錯誤率
- 觀察 log / metrics
- 有問題快速 rollback

## 重點

發布策略的核心是降低發布風險，並讓團隊在問題發生時能快速觀察、判斷與回復。
