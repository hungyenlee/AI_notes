## 原始資料

### 使用者

prompt、memory、context 差異

### Codex

這三個常被混用，但可以這樣分：

**Prompt**  
你「這一次」給 AI 的指令或問題。

例子：  
「請幫我用中文摘要這篇文章。」  
「你是資深工程師，請檢查這段程式碼。」

Prompt 是你主動輸入的任務要求。

**Context**  
AI 在回答當下「能看到、能參考」的所有資訊。

它可能包含：

- 你的 prompt
- 前面對話內容
- 貼上的文件
- 系統規則
- RAG 找回來的資料
- 工具執行結果

Context 比 prompt 大。Prompt 是 context 的一部分。

**Memory**  
AI 跨越多次對話後「記住」的資訊，通常是比較長期的偏好或事實。

例子：

- 你偏好繁體中文
- 你正在做某個專案
- 你喜歡簡潔回答
- 你的公司內部術語定義

Memory 不一定每次都完整出現在當下對話裡，但系統可能會在需要時拿來用。

一句話比較：

| 名稱 | 是什麼 | 時間尺度 |
|---|---|---|
| Prompt | 這次你下的指令 | 當下 |
| Context | AI 這次回答時看得到的全部資訊 | 當下/本輪對話 |
| Memory | AI 長期記住的資訊 | 跨對話 |

更直覺地說：

**Prompt 是你現在問的話。  
Context 是 AI 現在手上的資料包。  
Memory 是 AI 之後還可能記得的筆記。**

### 使用者

memory 會自己記住嗎? 會記在哪裡?

### Codex

不一定，取決於你用的是哪個系統/產品，以及有沒有開啟 memory 功能。

一般來說：

**Memory 不等於聊天紀錄。**

AI 當下能看見的是 `context`，也就是目前對話內容和系統提供的資訊。  
而 `memory` 是系統另外保存的長期資訊，例如「使用者偏好繁體中文」、「正在做某個專案」。

它通常有幾種情況：

| 類型 | 會不會自己記 | 存在哪裡 |
|---|---|---|
| 當前對話 context | 會暫時保留 | 這個聊天視窗/上下文裡 |
| 聊天紀錄 | 產品可能保存 | 服務商的聊天紀錄系統 |
| 長期 memory | 視設定而定，可能自動/半自動 | 服務商的記憶系統或使用者帳號資料 |
| App 自己做的 memory | 開發者設計決定 | 資料庫、向量資料庫、檔案、Redis 等 |

以 AI App 開發來說，模型本身通常**不會真的把事情寫進腦袋**。  
如果你想讓它「記住」，通常要你自己做一層：

1. 判斷哪些資訊值得記
2. 存到資料庫
3. 下次對話時再取回
4. 放進 context 給模型參考

所以答案是：

**模型本身不會永久記住；是否會記住，是產品或應用層決定的。記憶通常存在帳號資料、聊天紀錄、資料庫或向量資料庫裡。**

### Codex

`/compact` 的作用是：**把目前很長的對話濃縮成摘要，釋放 context/token 空間，讓 Codex 可以繼續工作。**

你可以把它想成：

**原本整本聊天紀錄太長了，塞不進 AI 的工作記憶；`/compact` 會把前面內容整理成重點筆記，留下後續需要的資訊。**

它適合用在：

- 對話跑很久
- 做了一大串修改、查了很多資料
- 快接近 context 上限
- 想讓 AI 繼續同一個任務，但不要被過長歷史拖慢或塞爆

它不是：

- 不是清除對話：`/clear` 比較像重新開始
- 不是永久 memory：不等於記到你的帳號長期記憶
- 不是備份完整紀錄：壓縮後通常只保留摘要，細節可能會少掉

一句話：

**`/compact` 是把目前對話「壓縮成重點摘要」，讓 AI 保留重要脈絡、騰出空間繼續處理。**
